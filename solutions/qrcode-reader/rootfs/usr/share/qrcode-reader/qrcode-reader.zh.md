# 二维码识别 — 集成说明

解码画面里的每一个二维码，并把内容通过 MQTT 发出。检测用 [quirc](https://github.com/dlbeer/quirc) 跑在 CPU 上——**不需要模型，不占用 TPU，没有任何东西要下载**。

一帧里的多个二维码在同一次解码中全部读出，这也是它能当固定式扫码器用（传送带、收银台上方）而不只是个手持扫码 App 的原因。

## MQTT 输出

主题：`recamera/qrcode-reader/results`，每处理一帧发一条。

```json
{
  "type": "qrcode",
  "frame": 4821,
  "qr_found": true,
  "detect_cost_ms": 34.10,
  "codes": [
    {
      "text": "https://www.seeedstudio.com",
      "points": [[0.31, 0.28], [0.55, 0.29], [0.54, 0.53], [0.30, 0.52]]
    }
  ]
}
```

- `codes[].text` —— 解出的内容，原样给出。做了 JSON 转义，所以二进制和多行内容也能完整传出。
- `codes[].points` —— 四个角点，**归一化到出流画面的 [0,1]**，顺序就是 quirc 返回的顺序（正放时为 左上、右上、右下、左下）。旋转的码保持同样的绕向，所以这个四边形可以直接画，不用再排序。
- `qr_found` —— 什么都没解出来时为 false 且 `codes` 为空数组。**两种情况都会发消息**，订阅方才能区分「画面里没有码」和「应用挂了」。
- `detect_cost_ms` —— 这一帧的解码耗时，不含取流。

## 视频

- RTSP：`rtsp://<设备IP>:8554/live0` —— 干净画面，不带叠加。
- Console 预览：`ws://<设备IP>:8001/`（H.264）与 `ws://<设备IP>:8001/results`（JSON）。叠加层会框出每个解出的码并显示内容。
- 快照：`http://<设备IP>:8001/snapshot.jpg`。

## 配置

`/etc/qrcode-reader.conf`，由 init 脚本读取：

| 键 | 默认值 | 含义 |
|---|---|---|
| `MQTT_HOST` / `MQTT_PORT` | `localhost` / `1883` | 要发布到的 broker |
| `MQTT_TOPIC` | `recamera/qrcode-reader/results` | 结果主题 |
| `RTSP_ENABLED` | `1` | 置 `0` 关闭 RTSP 出流 |
| `STREAM_WIDTH` / `STREAM_HEIGHT` / `STREAM_FPS` | `1280` / `720` / `30` | 编码出流参数 |
| `CAMERA_WIDTH` / `CAMERA_HEIGHT` / `CAMERA_FPS` | `1280` / `720` / `10` | 检测用画面 |

**检测画面是有意开大的。** 这里大多数检测器跑 640×640，但 quirc 需要每个码元有足够像素，而二维码通常只占画面的一部分。实测 640×640 下现实中的码——尤其是手机屏幕上的——解不出来。1280×720 与传感器宽高比一致（定位图案不会被拉扁），面积约为前者的 2.25 倍。

## 相机摆位

- 让二维码在画面里占得比你以为需要的更大。**小于画面宽度约 1/6 就已经在可靠解码的边缘了。**
- 均匀的散射光。手机屏幕或过塑标签上的反光比光线不足更容易毁掉定位图案。
- 可以旋转、也能容忍一定倾斜；角度太斜会丢掉远端边缘的码元。

## 没有做的部分

- **不用模型**。这是传统 CPU 解码器，无需下载任何东西，也不和别的应用抢 TPU。
- **不读一维条码**，只读二维码。
- **没接隐私打码**：这个应用就是要读画面内容，遮住它等于失去意义。
